Guide: Part 1 §3–4

Every change lives in one of four places. You edit files in the working directory; git add puts the changes you choose into the staging area; git commit records them as a snapshot in your local history; git push copies those commits to GitHub. The return trip is git pull: it fetches commits that others (or Codex, or your other laptop) pushed, and merges them into your history and your files. Saying “save” to Codex runs add, commit, pull and push in one go.

In daily work you rarely type the four commands one by one. SAY

“sync”

Guide: Part 1 §2 · Part 2 §4.5

Before branching, look at the line you start from. Each commit stores a pointer to its parent, so history reads backwards: D knows C, C knows B, and so on back to A, off to the left. D is the README edit you just pulled. main is not a container of commits; it is just a name attached to the newest one, and HEAD tells you which name you are on. Start new work from main right after a pull, so your branch begins at GitHub's latest version.

Choose the undo tool by where the change is. In the working directory, git restore throws away your edits to a file; that cannot be undone, so the git-workflow skill asks before running it. A commit that exists only on your Mac can be taken back with git uncommit, which is reset --soft HEAD~1 and refuses if the commit is already on GitHub. Once a commit is pushed, use git revert and push the result: it adds a new commit that inverts the old one, so nobody's history is rewritten.

SAY

“Undo my last commit, I haven’t pushed”

Guide: Part 1 §7 · Terminal shortcut: git uncommit (refuses if pushed)

reset moves the branch name itself. With --soft, main goes back from X to C, and X's changes come back as staged changes, ready to be fixed and committed again; your files are not touched. X is no longer on any branch, but git reflog still lists it for weeks, and git branch rescue plus its hash brings it back. This rewrites history, so use it only for commits you have not pushed: git uncommit does exactly this and refuses if the commit is already on GitHub. reset --hard is different: it also throws away uncommitted edits, and those cannot be recovered.

Written guide: github-guide/ in contravariant/presentations (branch github-guide)

Everything in this deck reduces to three loops. Solo, in your own repository: sync, edit, save, straight on main. Collaborating, or for any change you want reviewed: start a branch, save as often as you like, propose, let it be reviewed, finish, then start the next piece of work. When something goes wrong, undo, choosing the tool by where the change is. Solid chips are verbs you say to Codex (most also have a git alias); dashed ones you do yourself, in RStudio or on GitHub. The habit that prevents most trouble: pull before you start, push when you stop.
